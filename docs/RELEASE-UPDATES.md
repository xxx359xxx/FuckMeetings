# Сборка и обновления

Исходники Windows и macOS должны собираться из одного проверенного коммита. Файл
`rust-toolchain.toml` фиксирует Rust **1.99.1** и автоматически выбирается rustup на
обеих платформах. На Windows установите rustup и среду Visual Studio Build Tools с
компонентами C++; затем `rustup toolchain install 1.99.1 --profile minimal` и
`rustup show active-toolchain`. На Mac для нативного модуля звука нужен Xcode.
Это версия Rust, а не отдельный релиз приложения; автоматически она не обновляется.

Mac-набор `src-tauri/resources/whisper` состоит из arm64 `whisper-cli`,
собранного из whisper.cpp b5454 с Accelerate, без Metal, и `libsystem-audio.dylib`.
Это сборочные ресурсы, а не модели Whisper. Бинарные файлы генерируются при
сборке и не хранятся в Git. Для их создания на Mac с Apple Silicon выполните:

```sh
bash scripts/build-macos-resources.sh
```

Скрипт загружает исходники b5454, проверяет SHA-256 и компилирует оба ресурса.
Нужны Xcode, инструменты командной строки и CMake. Исходник аудиомодуля —
`src-tauri/native/system_audio_bridge.swift`; текущий скрипт предназначен для arm64.

Обновления настроены на публичный ресурс:
`https://github.com/xxx359xxx/FuckMeetings/releases/latest/download/latest.json`.
Пока репозиторий приватный или `latest.json` отсутствует, проверка для обычных
пользователей не сработает. Приложение не должно требовать GitHub-токен у пользователя.

## Подпись обновлений

Публичный ключ проверки находится в `src-tauri/tauri.conf.json`. Закрытый ключ
и его пароль необходимо хранить вне репозитория, сохранять резервную копию и
никогда не публиковать; потеря ключа сделает невозможным выпуск обновлений для
уже установленных копий. На Mac подготовленная локальная пара лежит в
`work/release-signing` на уровень выше папки проекта: `update.key` и
`update-password.txt`. Эта папка не входит в исходники. Владелец проекта должен
перенести её в надёжное место, сохранить резервную копию и ограничить доступ.
Ключ подписи обновлений не заменяет подпись установщиков Windows и Apple Developer ID.

Перед каждой release-сборкой задать `TAURI_SIGNING_PRIVATE_KEY` (содержимое
закрытого ключа) и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` через безопасное хранилище
сборки, не записывая секреты в Git или логи. Включить на время release-сборки
`bundle.createUpdaterArtifacts: true` через отдельный файл `--config` и выполнить
`tauri build`; проверить, что созданы подписанные файлы `.sig`. Закрытый ключ и
пароль не должны попадать в приложение или `latest.json`.

Подготовить GitHub Release как draft; к одной версии приложить Windows NSIS
`*-setup.exe` и его `.sig`, Mac `.dmg` для первой установки и подписанный
`*.app.tar.gz` с `.sig` для обновлений. `latest.json` должен содержать версии,
HTTPS-ссылки и содержимое подписей для `windows-x86_64` и `darwin-aarch64`.
`requireSignedVersion` включён: используйте CLI, подписывающий версию обновления
(`tauri build` делает это автоматически). Tauri Action умеет формировать
`latest.json`; сначала проверить manifest и оба артефакта в draft, затем публикация
только по отдельному разрешению владельца. GitHub `releases/latest` не предназначен
для закрытого тестирования приватного репозитория или для выбора prerelease.

До публичного выпуска проверить полное обновление на чистых Windows и macOS:
версия N обнаруживает N+1, скачивает и проверяет подпись, устанавливает поверх
приложения и запускается; неправильная подпись отклоняется; текущие данные и
настройки сохранены. Проверить недоступный GitHub, прерванную сеть, режим записи,
несохранённую встречу и отказ пользователя от перезапуска. На Windows установка
закрывает приложение; на macOS нужен перезапуск. Выпуск для Intel Mac требует
отдельной сборки и совместимого нативного движка Whisper и модуля аудио.

Для удобного публичного распространения дополнительно настроить подпись и
нотариальное заверение Apple и подпись Windows; локальная ad-hoc подпись может
потребовать подтверждений Gatekeeper и повторной выдачи разрешений после смены
бинарного файла. Не переключать подписи и не сбрасывать разрешения пользователя
автоматически. Не публиковать релиз без отдельного указания владельца.
Для тестовых сборок macOS в `tauri.macos.conf.json` заданы ad-hoc подпись `-` и
выключенный hardened runtime, как в проверенной локальной сборке с аудио-модулем.
Для публичного выпуска подписать все вложенные исполняемые файлы и библиотеки
Developer ID, включить hardened runtime и выполнить нотариальное заверение через
release-конфиг; проверить загрузку аудио-модуля и обновление на чистом Mac.
